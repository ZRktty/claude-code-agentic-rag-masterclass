# 2. Supabase Schema + Auth

⚠️ **Medium** - well-trodden pattern, but RLS correctness and cross-tier token flow need care; only provably correct with a two-user test.

## Scope

Create the `threads` table + RLS via a migration, wire Supabase email/password auth into the frontend (sign up/in/out, session persistence, protected routes) and backend (JWT verification middleware).

**Not in scope**: thread CRUD endpoints, OpenAI conversation creation, chat UI (sub-plan 3). `openai_vector_store_id` is deliberately *not* added to `threads` here — sub-plan 4 owns that column via its own migration, keeping each sub-plan's migration self-contained.

## Tasks

1. **Migration** — `supabase/migrations/<timestamp>_create_threads_table.sql`:
   ```sql
   create table if not exists public.threads (
     id uuid primary key default gen_random_uuid(),
     user_id uuid not null references auth.users(id) on delete cascade,
     title text not null default 'New chat',
     openai_conversation_id text not null,
     created_at timestamptz not null default now(),
     updated_at timestamptz not null default now()
   );

   alter table public.threads enable row level security;

   create policy "Users can view own threads" on public.threads
     for select using (auth.uid() = user_id);
   create policy "Users can insert own threads" on public.threads
     for insert with check (auth.uid() = user_id);
   create policy "Users can update own threads" on public.threads
     for update using (auth.uid() = user_id) with check (auth.uid() = user_id);
   create policy "Users can delete own threads" on public.threads
     for delete using (auth.uid() = user_id);

   create index if not exists threads_user_id_idx on public.threads(user_id);

   create or replace function public.set_updated_at()
   returns trigger as $$
   begin new.updated_at = now(); return new; end;
   $$ language plpgsql;

   create trigger threads_set_updated_at
     before update on public.threads
     for each row execute function public.set_updated_at();
   ```
   - Apply via `npx supabase init` (if not already) → `npx supabase link --project-ref <ref>` → `npx supabase db push`. **Fallback** if CLI linking fails (no project ref/login available): apply the SQL directly via the Supabase Dashboard SQL editor and note this deviation in PROGRESS.md.
   - **Validate**: `select * from pg_policies where tablename = 'threads';` returns exactly 4 rows; `select relrowsecurity from pg_class where relname = 'threads';` returns `true`.

2. **Backend Supabase client factory** — `backend/src/lib/supabase.ts`: export a per-request user-scoped client factory, `getUserClient(accessToken: string) => createClient(url, anonKey, { global: { headers: { Authorization: \`Bearer ${accessToken}\` } } })`, so downstream queries are automatically RLS-scoped without hand-written `user_id` filters. Add `backend/src/lib/supabase-admin.ts` (service-role client) as a documented escape hatch, unused in Module 1 request paths.
   - **Validate**: a smoke import of the module resolves without throwing.

3. **Auth middleware** — `backend/src/middleware/auth.ts`: reads `Authorization: Bearer <token>`, calls `createClient(url, anonKey).auth.getUser(token)` (network round-trip to Supabase Auth — deliberately avoids hand-rolled JWT/JWKS verification so it works regardless of whether the project uses legacy HS256 or newer asymmetric signing keys), sets `c.set('user', user)` / `c.set('accessToken', token)` on success, returns 401 JSON on failure. Mount as `app.use('/api/*', authMiddleware)` in `backend/src/index.ts`, leaving `/health` public.
   - Add a throwaway debug route `GET /api/_whoami` returning `{ id, email }`.
   - **Validate**: `curl -H "Authorization: Bearer $TOKEN" localhost:3001/api/_whoami` → 200; `curl localhost:3001/api/_whoami` (no header) → 401.

4. **Frontend Supabase client** — `frontend/src/lib/supabase.ts`: `createClient(import.meta.env.VITE_SUPABASE_URL, import.meta.env.VITE_SUPABASE_ANON_KEY, { auth: { persistSession: true, autoRefreshToken: true } })`.
   - **Validate**: `bun --cwd frontend run build` compiles with no TS errors referencing this file.

5. **Auth context** — `frontend/src/lib/auth-context.tsx`: React context wrapping `supabase.auth.onAuthStateChange` + `getSession()`, exposing `{ user, session, loading, signIn, signUp, signOut }`. Wrap the app root in `<AuthProvider>`.
   - **Validate**: sign up a test user via the UI (task 6), confirm the user appears in the Supabase Auth dashboard; refresh the page, confirm the session persists.

6. **Auth pages** — `frontend/src/pages/SignIn.tsx`, `frontend/src/pages/SignUp.tsx` using shadcn `Input`/`Button`/`Card`/`Label`, with inline error rendering of Supabase error messages.
   - **Validate**: wrong password on sign-in shows an inline error; duplicate-email sign-up shows an inline error; successful sign-in redirects to the (placeholder) chat shell route.

7. **Routing + protected routes** — install `react-router` (verify current major version), `frontend/src/routes.tsx` defining `/sign-in`, `/sign-up`, and a protected `/` behind a `<ProtectedRoute>` component that redirects unauthenticated users to `/sign-in` and shows a loading state while the session resolves.
   - **Validate**: with no session, navigating to `/` redirects to `/sign-in`; after signing in, `/` is reachable directly.

8. **Sign-out control** — placeholder header button calling `signOut()`, redirecting to `/sign-in`.
   - **Validate**: click sign-out, confirm redirect; note the current access token remains cryptographically valid until natural expiry even after sign-out (refresh token is invalidated) — expected Supabase behavior, not a bug.

## Risks to flag

- **Email confirmation setting**: check Supabase Auth project settings — if "Confirm email" is enabled, sign-up won't produce an immediately usable session; either disable it for dev/testing or build the "check your email" UX state.
- **RLS proof requires two real users.** A single-user test can't distinguish "RLS is working" from "RLS doesn't exist" — validate cross-user isolation once two accounts exist (finish this check in sub-plan 3, once thread creation exists).
