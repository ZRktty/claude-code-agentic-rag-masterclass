# 1. Repo Scaffolding

⚠️ **Medium** - mostly boilerplate, but Tailwind v4 + shadcn CLI + monorepo workspace wiring has real yak-shaving risk if versions have moved since this was written.

## Scope

Stand up the monorepo skeleton for both apps, get a "hello world" running end-to-end on both sides, fix the stale Python/Pydantic references in CLAUDE.md/README.md, and establish PROGRESS.md conventions for the rest of the module.

**Not in scope** (deferred to later sub-plans): Supabase schema, auth, OpenAI/LangSmith code, chat logic.

## Tasks

1. **Root workspace setup.** Create root `package.json` with `"workspaces": ["frontend", "backend"]` (Bun workspaces — Bun is already installed and runs Vite fine, use it as the single package manager for both apps). Update root `.gitignore` to include `node_modules/`, `dist/`, `.env`, `.env.local`, `!.env.example`, `.DS_Store`.
   - **Validate**: `bun install` at repo root completes with no errors; `git status --porcelain` shows no `node_modules` entries.

2. **Backend skeleton** — `backend/package.json`, `backend/tsconfig.json`, `backend/src/index.ts`:
   - `bun add hono` inside `backend/`.
   - `index.ts` exports a Bun-native handler: `export default { port: Number(process.env.PORT ?? 3001), fetch: app.fetch }`, with `app.use(cors({ origin: 'http://localhost:5173' }))` from `hono/cors` and a `GET /health` route returning `{ status: 'ok' }`.
   - `backend/.env.example`:
     ```
     PORT=3001
     SUPABASE_URL=
     SUPABASE_ANON_KEY=
     SUPABASE_SERVICE_ROLE_KEY=
     OPENAI_API_KEY=
     OPENAI_MODEL=
     LANGSMITH_TRACING=true
     LANGSMITH_API_KEY=
     LANGSMITH_PROJECT=agentic-rag-masterclass
     ```
     Leave `OPENAI_MODEL` blank with a comment to fill in a currently-available model name at implementation time — don't hardcode a possibly-stale default.
   - **Validate**: `bun --cwd backend run src/index.ts` starts the server; `curl -s localhost:3001/health` returns `{"status":"ok"}` with HTTP 200.

3. **Frontend skeleton** — scaffold via `bun create vite@latest frontend -- --template react-ts`, then Tailwind + shadcn:
   - Tailwind: verify current install path before assuming v3's `tailwind.config.js`/`postcss.config.js` flow — Tailwind v4 typically uses the `@tailwindcss/vite` plugin plus `@import "tailwindcss";` in the root CSS with little/no config file. Check current docs at implementation time.
   - Configure path alias `@/*` in `frontend/tsconfig.json` and `frontend/vite.config.ts` (required by shadcn).
   - Run `npx shadcn@latest init` then `npx shadcn@latest add button input card label` to prove the pipeline. Confirm the current CLI prompt set — it changes across releases.
   - `frontend/.env.example`:
     ```
     VITE_SUPABASE_URL=
     VITE_SUPABASE_ANON_KEY=
     VITE_API_BASE_URL=http://localhost:3001
     ```
   - **Validate**: `bun --cwd frontend run dev` starts Vite on `:5173`; loading the root page shows a rendered shadcn `<Button>` with Tailwind utility classes applied and no console errors.

4. **Root dev scripts** — add `dev:backend`, `dev:frontend`, and a combined `dev` script (e.g. via `concurrently`) to root `package.json`.
   - **Validate**: `bun run dev` boots both processes without port conflicts; `curl localhost:3001/health` and `curl -sI localhost:5173` both succeed.

5. **Update `CLAUDE.md`** — replace `Backend: Python + FastAPI`, the `venv` rule, and `Use Pydantic for structured LLM outputs` with the Node/Hono/Bun stack and a Zod-based equivalent rule (`Use Zod for structured LLM outputs and request/response validation`). Leave all other rules intact (RLS, SSE streaming, LangSmith, planning conventions, Module 2+ stateless-completions note).
   - **Validate**: `grep -i "python\|pydantic\|venv" CLAUDE.md` returns no matches.

6. **Update `README.md`** tech stack table to match (`Backend: Python, FastAPI` → `Node.js, Hono, Bun`), leaving Docling/later-module references untouched since they're out of Module 1 scope.
   - **Validate**: `grep -i "python\|fastapi" README.md` returns no matches.

7. **Update `PROGRESS.md`** with a Module 1 checklist reflecting the 4 sub-plans (`[ ] 1. Repo scaffolding`, `[ ] 2. Supabase schema + auth`, `[ ] 3. Chat core`, `[ ] 4. File attach + observability`), following the existing `[ ]/[-]/[x]` convention.
   - **Validate**: manual read-through against the convention already documented in the file.

8. **Confirm env-file gitignore behavior.** No root-level aggregated `.env.example` is needed — env files are per-app (`frontend/.env.example`, `backend/.env.example`) intentionally, to avoid mixing `VITE_`-prefixed browser-exposed vars with server secrets.
   - **Validate**: create throwaway `backend/.env` and `frontend/.env.local`, run `git status --porcelain`, confirm neither appears; delete the throwaway files.

## Key specifics / risks

- Bun natively serves Hono via the `fetch` export shape shown above — no `@hono/node-server` needed.
- Tailwind v4 setup differs meaningfully from v3 tutorials; verify current steps before executing.
- shadcn CLI prompts/flags change between releases; don't assume the exact prompt sequence.
